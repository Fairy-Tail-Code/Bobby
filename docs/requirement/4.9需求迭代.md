##  2 长时运行应用开发的 Harness 设计

> 作者：Prithvi Rajasekaran（Anthropic Labs 团队）

### 核心结论

用**生成器 + 评估器**的多智能体结构（借鉴 GAN 思想），可以显著突破单 Agent 在设计质量和长时编码任务上的天花板。最终形态是**三智能体架构（Planner → Generator → Evaluator）**，能在数小时的无人值守会话中产出完整的全栈应用。

---

### 两个关键问题

(要求：可插拔地实现以下两个能力——上下文重置&&上下文压缩)

#### 1. 上下文窗口失控（Context Anxiety）

模型在上下文接近上限时会提前收尾。解决方案是**上下文重置**：清空上下文、启动新 Agent，并通过结构化交接文件传递状态。这不同于 compaction（压缩历史摘要）——重置给 Agent 一个干净的起点，彻底消除"焦虑"。

> 注：Opus 4.6 已大幅改善该问题，新架构中可直接去掉重置机制，改用 SDK 的自动 compaction。

#### 2. 自我评估偏宽松

Agent 评价自己的输出时倾向于给高分，哪怕质量平庸。**将生成和评估分离**是核心解法——独立的 Evaluator Agent 更容易被调教成严格的审查者。

---

### 前端设计：让主观质量可量化

给 Generator 和 Evaluator 同一套评分标准（四个维度），让它们有共同的"品味语言"：

| 维度         | 含义                                                         | 权重                   |
| ------------ | ------------------------------------------------------------ | ---------------------- |
| **设计质量** | 色彩、排版、布局是否形成统一的视觉语言和氛围                 | 高                     |
| **原创性**   | 是否有定制化决策，还是模板/默认样式/AI 套路（如白卡+紫渐变） | 高                     |
| **工艺**     | 字体层级、间距、色彩对比等基本功                             | 低（模型默认表现已够） |
| **功能性**   | 用户能否理解界面并完成任务                                   | 低（模型默认表现已够） |

Evaluator 使用 **Playwright MCP** 直接操作运行中的页面进行评分，而非评估静态截图。

#### 循环流程

1. Generator 生成 HTML/CSS/JS 前端
2. Evaluator 浏览页面、截图、按四维打分并写出详细批评
3. 批评反馈给 Generator，Generator 根据得分趋势决定**精修**（趋势良好）还是**重构**（方向不对）
4. 重复 5~15 轮

---

### 全栈编码：三智能体架构

#### 架构设计

用户 1~4 句话的 Prompt ↓ 【Planner】 扩展为完整产品规格（功能列表、技术架构、视觉设计方向） 强调：高层交付物，不指定实现细节，主动植入 AI 功能 ↓ 【Generator】（按 Sprint 逐个特性构建） 技术栈：React + Vite + FastAPI + SQLite/PostgreSQL + Git 每个 Sprint 开始前与 Evaluator 协商"Sprint 合同"（明确验收标准） Sprint 结束后自评，再交给 Evaluator ↓ 【Evaluator】（每个 Sprint 后评审） 使用 Playwright MCP 点击运行中的应用 按合同标准验收；任一维度低于阈值则 Sprint 失败 输出具体 Bug 报告（指明文件行号、根因），Generator 修复后重跑

#### Sprint 合同机制（暂时不使用sprint合同机制，默认模型能力足够）

在每个 Sprint 开始前，Generator 提案"我要做什么、怎么验证"，Evaluator 审核后双方通过文件交换达成一致，避免规格歧义导致的方向偏差。

#### Evaluator 调教要点

开箱即用的模型是糟糕的 QA Agent——它会发现问题，然后自我说服"其实不严重"。需要反复阅读评估日志，找出 Evaluator 判断与人工判断的偏差点，针对性修改 Prompt，直到打分标准与预期对齐。

---

### 架构演进：去掉 Sprint 构件

随着 Opus 4.6 的发布，模型原生能力提升，Sprint 分解不再必要：

- **去掉 Sprint 构件**：Generator 可在单次连续会话中工作 2+ 小时不失控
- **Evaluator 改为端到端一次性 QA**：不再逐 Sprint 评审
- **Planner 和 Evaluator 保留**：仍有明显价值

> **核心原则**：Harness 的每个组件都是对"模型无法独立完成"的假设编码。模型越强，需要的脚手架越少。要定期重新审视哪些组件还是"承重墙"，哪些已经多余。

### 核心设计原则总结

1. **生成与评估分离**：是提升输出质量的最强杠杆
2. **主观质量可量化**：通过具体评分标准将"好不好"转化为"符不符合原则"
3. **评估器用实时交互，而非静态截图**：Playwright MCP 直接操作页面
4. **Planner 只定义 What，不规定 How**：避免高层错误级联到实现
5. **每次新模型发布，重新审视 Harness**：去掉不再承重的部分，为新能力留空间

- 在生成签名时始终保留 `**kwargs`，吞掉 beta 注入的 `__ctx__`
- 零参数工具生成 `async def tool(**kwargs)`，避免空参数列表语法错误
- 可选参数未提供时不再下发为 `null`，避免把“省略参数”错误变成“显式传 None”
- 增加针对零参数工具和可选参数省略场景的回归测试

### 验收标准

- beta network 角色初始化时，零参数 MCP 工具不再因动态 `exec` 抛 `SyntaxError`
- 带显式参数的 MCP 工具可继续被 beta 正确校验
- AG2 beta 注入 `__ctx__` 时不会污染实际传给 MCP server 的参数字典
- 未传入的可选参数不会被错误透传为 `None`

## AG2 beta network 纯文本回复降级修复

### 新需求

- 当前专家模式在 DeepSeek 等不支持 `response_format=json_schema` 的后端上，依赖 prompt 要求模型直接输出 `NetworkTurn` JSON
- 但实际运行中，PM 首轮仍可能返回自然语言介绍和提问，例如 `[PM] 你好...你想做什么项目？`
- `orchestration/network_runtime.py` 当前只会尝试 `model_validate_json()`，失败后直接抛错，导致整个 session 中断
- 需要保证非 schema 后端即使偶发返回纯文本，也能尽量安全降级，而不是让会话直接报错退出

### 本次落地范围

- 收紧 beta network 非 schema contract，明确禁止身份前缀、寒暄包裹和 JSON 外壳
- `network_runtime` 在字符串不是合法 JSON 时，尝试基于角色和文本内容推断安全的 `next_step`
- 至少覆盖 PM 首轮“自然语言提问用户”这类高频场景，自动降级为 `ask_user`
- 增加回归测试，覆盖纯文本提问降级和非 schema prompt 约束

### 验收标准

- 非 schema 后端返回 `[PM] ...？` 这类纯文本时，不再因为 `NetworkTurn` JSON 校验失败而中断 session
- PM 首轮自然语言提问可以被编排层识别为 `ask_user`
- DeepSeek 路径下角色 prompt 明确包含“只输出 JSON / 不要输出 `[PM]` 前缀”的约束

## AG2 beta stream `__ctx__` 回调兼容修复

### 新需求

- 首轮问答成功后，第二轮一旦触发真实 tool call，会在 beta stream 订阅链路抛出 `context Field required`
- 报错位置表面上出现在 `_on_tool_call`，但进一步确认发现当前 AG2 beta 自带的 `MemoryStream` 默认订阅 `storage.save_event` 也仍使用旧式 `context` 参数
- beta runtime 现在通过 `__ctx__` 注入上下文，因此只要 stream 上有沿用旧签名的订阅回调，tool event 一发出就会触发 fast_depends/Pydantic 校验失败
- 需要让 beta network 在多轮对话和真实工具调用场景下稳定运行

### 本次落地范围

- `network_runtime` 中为角色会话改造 `MemoryStream` 创建方式，替换默认存储订阅为 `__ctx__` 兼容包装器
- `_on_tool_call` 前端观察者同步改为兼容 `__ctx__` 注入
- 增加直接 `stream.send(ToolCallEvent)` 的回归测试，覆盖“第二轮才爆”的真实路径

### 验收标准

- beta network 第二轮发生工具调用时，不再因为 `context` 缺失而中断 session
- `ToolCallEvent` 仍可写入 stream history
- 前端工具调用通知仍可正常触发

## DeepSeek beta 路径切回 AG2 推荐用法

### 新需求

- 当前专家模式继续保留 AG2，不切换自研 runtime
- 但 `ag2==0.11.5` 的 `OpenAIConfig` 走 `chat.completions`，默认不会透传 DeepSeek 需要的 `extra_body.thinking.disabled`
- 同时非原生结构化输出路径此前依赖自定义 prompt JSON contract，不够贴近 AG2 beta 的推荐用法
- 需要在尽量保留 AG2 的前提下，让 DeepSeek 路径先可用

### 本次落地范围

- DeepSeek 后端不再使用原生 `response_schema=NetworkTurn`，改用 AG2 自带 `PromptedSchema(NetworkTurn)`
- 新增本地 `DeepSeekOpenAIConfig`，仅用于给 `chat.completions.create` 透传 `extra_body={"thinking":{"type":"disabled"}}`
- 保留 OpenAI 兼容后端继续使用原生 `OpenAIConfig + response_schema=NetworkTurn`
- 增加回归测试，覆盖 DeepSeek config 类型、PromptedSchema 绑定与 `extra_body` 注入

### 验收标准

- DeepSeek 路径下不再触发 `reasoning_content must be passed back to the API`
- DeepSeek 角色 agent 继续返回结构化 `NetworkTurn`
- OpenAI 兼容后端不受影响，仍保留原生 schema response path

## 工具调用前端通知降级

### 新需求

- 当前 beta network 第二轮真实触发工具调用后，会通过前端发送“正在执行工具”的提示消息
- 微信网关在该提示消息上偶发返回 `ret=-2 errmsg=unknown`
- 该异常当前会沿 beta stream 订阅链路回抛，导致工具通知失败直接打断整条 session
- 需要保证工具调用通知只是附加观测，不影响 AG2 主流程可用性

### 本次落地范围

- `orchestration/network_runtime.py` 中的 `_RoleSession._on_tool_call()` 改为 best-effort 前端通知
- 当前端 `on_tool_call` 抛错时，仅记录 warning，不再向 beta stream 回抛
- 增加回归测试，覆盖“前端工具通知失败但 `ToolCallEvent` 仍成功写入 history”的场景

### 验收标准

- 微信工具调用提示发送失败时，不再导致专家模式 session 直接报错退出
- 工具调用本身和 `ToolCallEvent` history 写入继续完成
- 降级范围仅限 tool-call 提示消息，不改变普通主回复的发送语义

## PromptedSchema 代码围栏兼容

### 新需求

- DeepSeek beta 路径已经使用 `PromptedSchema(NetworkTurn)`，但模型实际仍可能返回带 ```json markdown 围栏的结果
- 当前 AG2 0.11.5 的 `AgentReply.content()` 会在 `PromptedSchema.validate()` 内部直接做严格 `validate_json()`
- 导致即使围栏内 JSON 合法，也会在进入项目本地兜底前先抛 `Invalid JSON`
- 需要保证 beta network 对这类“格式外壳正确性不足但内容本身可解析”的响应有本地兼容能力

### 本次落地范围

- `network_runtime.py` 不再依赖 `reply.content(retries=1)` 直接拿 `NetworkTurn`
- 改为优先读取 `reply.body` 原文，并复用本地 `_coerce_network_turn()` 去围栏解析
- 首次本地解析失败时，再补一次“只返回裸 JSON”的纠正请求
- 增加回归测试，覆盖 `PromptedSchema(NetworkTurn)` 返回 fenced JSON 的场景

### 验收标准

- DeepSeek / PromptedSchema 路径下，返回 ```json 包裹的 `NetworkTurn` 不再导致 session 中断
- 围栏内合法 JSON 可被本地 runtime 正常解析
- 原有纯文本降级和 tool-call 通知降级能力不受影响
