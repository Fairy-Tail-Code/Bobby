## 一、变更概览

本次重构包含两项核心改动：

1. **前端解耦**：将飞书从核心逻辑中剥离，通过 `Frontend` Protocol + `ChannelAdapter` 抽象实现可插拔前端
2. **事件驱动重构**：用 AG2 原生 `a_run_group_chat_iter` 替代轮询式消息拦截，实现事件驱动输出

---

## 二、前端解耦（commit `a520141`）

### 问题

`SwarmSession` 和 `SessionManager` 直接依赖 `FeishuBotService` 类型，核心模块 import 飞书实现类。`channel_proxy.py` 中使用 `isinstance(ChannelFeishuService)` 破坏了 `ChannelAdapter` 抽象。无法添加 CLI / Web 等其他前端。

### 方案

引入两层抽象：

- **`Frontend` Protocol**（`infrastructure/frontend.py`）：消息推送接口
  - `send_text(chat_id, text)` — 推送文本
  - `stream_token(chat_id, agent_name, token)` — 流式 token（可选）
  - `on_tool_call(chat_id, agent_name, tool_name)` — 工具调用通知

- **`ChannelAdapter` 基类**（`infrastructure/channel/channel.py`）：HITL 通道接口
  - `send()` — 向用户发送审批请求
  - `wait_reply(request_id, timeout)` — 阻塞等待用户回复
  - `inject_reply(request_id, text)` — 注入外部回复（如飞书消息触发）

### 改动文件

| 文件 | 改动 |
|------|------|
| `infrastructure/frontend.py` | **新建** — Frontend Protocol |
| `infrastructure/channel/channel.py` | **扩展** — 基类加 `wait_reply()` |
| `infrastructure/swarm_session.py` | `bot: FeishuBotService` → `frontend: Frontend`，`channel_factory` 注入 |
| `infrastructure/session_manager.py` | `_bot` → `_frontend`，透传 factory 和 hitl_mode |
| `agents/channel_proxy.py` | 删除 `isinstance` hack，统一用 `wait_reply()` |
| `server.py` | 创建 Frontend 实例后注入 SessionManager |

### 未改动

- `agents/PM.py`, `planner.py`, `generator.py`, `evaluator.py` — 无飞书依赖
- `infrastructure/feishu_bot.py` — 保持原样，作为 Frontend 的一个实现
- `config/config.py` — 配置层自然耦合，保留

## 三、事件驱动重构（commit `c06ad8f` + `3235d0e`）

### 问题

重构前使用轮询式拦截 agent 消息：在每个 agent 上注册 `hook_lists` 回调，LLM 回复后触发 `_flush_message()` 轮询检查新消息。这种方式：
- 依赖 AG2 内部 `hook_lists` 结构（不稳定）
- 延迟高（轮询间隔）
- 代码复杂（消息去重、sender 判断、轮询状态管理）

### 方案

使用 AG2 v0.7+ 原生 `a_run_group_chat_iter()`，直接迭代事件流：

```python
async for event_response in a_run_group_chat_iter(
    pattern=pattern,
    messages=messages_input,
    max_rounds=self._harness_config.max_rounds,
):
    event = event_response.content

    if isinstance(event, TextEvent):
        # agent 文本输出 → 推送到前端
    elif isinstance(event, ToolCallEvent):
        # 工具调用通知
    elif isinstance(event, RunCompletionEvent):
        # swarm 运行完成
    elif isinstance(event, ErrorEvent):
        # 错误处理
```

### 关键 API 说明

- `a_run_group_chat_iter()` 是**普通函数**（不是 async generator 也不是 coroutine）
- 返回 `AsyncRunIterResponse` 对象，实现了 `__aiter__` / `__anext__`
- 内部使用后台线程 + `run_in_executor` 实现异步迭代
- **不需要** `await`（之前的 bug 就是在它前面加了 `await`）

### 踩坑记录

| 问题 | 原因 | 解决 |
|------|------|------|
| `TypeError: object AsyncRunIterResponse can't be used in 'await' expression` | `a_run_group_chat_iter()` 返回值不是 coroutine，加了多余的 `await` | 去掉 `await`，直接 `async for ... in a_run_group_chat_iter(...)` |
| LLM 调用 200 OK 后无事件输出 | 同上，`await` 导致类型错误，swarm session 异常退出 | 同上 |

## 五、如何添加新前端

### Step 1: 实现 Frontend Protocol

```python
# infrastructure/frontend_xxx.py
class XxxFrontend:
    async def send_text(self, chat_id: str, text: str) -> None:
        ...  # 推送消息到用户

    async def on_tool_call(self, chat_id: str, agent_name: str, tool_name: str) -> None:
        ...  # 可选：通知工具调用

    async def stream_token(self, chat_id: str, agent_name: str, token: str) -> None:
        ...  # 可选：流式输出
```

### Step 2: 实现 ChannelAdapter（如需 HITL）

```python
class XxxChannel(ChannelAdapter):
    async def send(self, recipient, subject, body, request_id):
        ...

    async def wait_reply(self, request_id, timeout=300):
        ...

    async def inject_reply(self, request_id, text):
        ...
```

### Step 3: 在 server.py 中注入

```python
frontend = XxxFrontend()
session_manager = SessionManager(
    frontend=frontend,
    channel_factory=lambda chat_id: XxxChannel(),
    hitl_mode="xxx",
    ...
)
```

核心代码（agents、session、orchestration）无需任何改动。
